## Network Unit（管控单元）

管控单元用来组织**一组采用相同接入方式管理的节点**。每个单元属于一个[管控区域](networkarea.md)，决定其中的 Agent 是直接连接 GSE，还是经过本单元的 Proxy 连接上游。

## 为什么需要管控单元

同一个管控区域内，节点的管理路径可能不同。例如，一组主机能直接访问 GSE，另一组主机处于隔离网络中，需要经过 Proxy。将它们划分到不同的管控单元，就能分别配置管理路径，而不必改变主机的管控区域。

**区域描述网络归属，单元描述管理路径，接入点描述单元之间的连接地址。** 管控单元不是业务分组，也不是一个新的 IP 区分范围：同一区域内，划分多个单元不能解决主机内网 IP 重复的问题。

## 直连与非直连

创建单元时选择直连或非直连，对应 `is_direct` 字段。

| 类型 | Agent 的连接路径 | 需要配置什么 | Proxy 要求 |
| --- | --- | --- | --- |
| 直连单元（`true`） | Agent 直接连接 GSE。 | “直连配置”中的 `cluster`、`file`、`data` 三组 GSE 地址。 | 不使用 Proxy，不能在其中安装 Proxy。 |
| 非直连单元（`false`） | Agent 连接本单元的 Proxy，Proxy 再连接上游。 | 选择上游管控区域、管控单元和[接入点](accesspoint.md)。 | 需要运行正常的 Proxy 提供控制、文件和数据通道。 |

三类通道一般选择同一个上游接入点；只有它们需要连接不同入口时，才在高级配置中分别选择。

直连与非直连不只是配置上的区别，使用前还需要满足实际网络条件：

- **直连单元**：Agent 能访问所填的 GSE 地址；普通在线安装还需要目标主机能访问节点管理的 HTTP 下载、回调服务。自动安装时，还需允许 Backend 登录目标主机执行安装。
- **非直连单元**：Agent 能访问本单元的 Proxy，Proxy 能访问所选上游接入点。通过本单元在线安装，还需要具备安装能力、且 Relay 插件运行正常的 Proxy。Relay 提供安装跳板、HTTP 下载和回调转发。

**不能把“已有 Proxy”直接等同于“可以安装”。** 通信通道和安装能力都需要就绪；创建单元或保存地址不会自动打通网络。

## 如何使用

1. 在主机所属的管控区域下创建单元，填写名称并选择直连或非直连。单元创建后，所属区域和直连类型不能通过编辑切换。
2. 直连单元填写 GSE 直连地址；非直连单元选择能够访问的上游接入点。
3. 非直连单元先准备 Proxy。空单元中的第一台 Proxy 需要通过跨单元安装或离线安装建立；具备安装能力后，才能通过本单元继续安装 Agent 和其他 Proxy。具体方式见[节点传输模式](../node/control_mode.md)。
4. 安装 Agent 时选择目标单元。主机所属的 CMDB 管控区域必须与该单元所属区域一致。
5. 如果其他单元需要通过本单元连接上游，再配置“下游接入点”。它供其他单元的 Proxy 使用，不是本单元 Agent 的连接配置，详见[接入点](accesspoint.md)。

修改直连地址或上游选择后，已有节点不会立即更新配置，需要重载对应的 Agent 或 Proxy。重载会重启节点服务，应安排合适的操作时间，并确认任务成功。

## 默认直连单元自动创建

默认管控区域（ID 为 `0`）支持通过 Backend 配置 `networkUnit.defaultDirectUnit` 自动创建一个直连单元。默认关闭；启用后，定时管控区域同步会在默认区域已同步、且其中尚无直连单元时创建，已有直连单元则跳过。

启用前必须填写环境中真实可用的 `clusterEndpoints`、`fileEndpoints` 和 `dataEndpoints`。该配置只负责创建单元，不保证网络连通，也不会把默认区域中的其他单元变成直连单元。配置方法见[默认直连单元配置](../../operation/installation/default_direct_unit.md)。
