## Network Area（管控区域）

管控区域用来区分**主机所属的网络范围**。它对应 CMDB 中的管控区域（也叫云区域），区域 ID 也用于 GSE 识别主机所属的网络。

## 为什么需要管控区域

不同网络可能使用相同的内网 IP。例如，两个独立 VPC 中都可能有一台 IP 为 `127.0.0.1` 的主机。将它们放在不同的管控区域中，节点管理就能区分这两台主机，而不会只凭 IP 把它们混为一谈。

同一个管控区域内，不应把相同内网 IP 用于不同主机。安装检查会按“管控区域 + 内网 IP”查找已有主机；在同一区域内新建管控单元，不能解决 IP 重复的问题。

## 与管控单元、接入点的关系

| 概念                       | 回答的问题                                               |
| -------------------------- | -------------------------------------------------------- |
| 管控区域                   | 主机属于哪个网络范围？                                   |
| [管控单元](networkunit.md) | 这些节点通过什么路径接受管理：直连 GSE，还是经过 Proxy？ |
| [接入点](accesspoint.md)   | 其他管控单元通过哪些地址连接到这里？                     |

一个管控区域可以包含多个管控单元。例如，同一区域内，一组节点可以直接连接 GSE，另一组节点需要经过 Proxy，就可以分别放入直连单元和非直连单元。

**区域描述网络归属，单元描述管理路径。** 管控区域不是业务分组，也不保证区域内的主机彼此可达。ID 为 `0` 的区域是默认管控区域，但其中的管控单元并不一定都是直连单元。

## 如何使用

1. 从 CMDB 同步已有管控区域，或在节点管理中创建区域。创建时填写名称和云服务商，区域也会在 CMDB 中创建。
2. 在区域下创建管控单元，根据实际网络条件选择直连或非直连，并配置连接地址或上游接入点。
3. 安装 Agent 时选择目标管控单元。主机所属的 CMDB 管控区域必须与该单元所属区域一致。

创建区域只建立归属信息，不会自动建立 Proxy、配置接入点或打通网络。开始安装前，仍需准备好管控单元所需的服务和网络连通条件。
