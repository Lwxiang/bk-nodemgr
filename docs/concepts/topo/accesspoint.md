## Access Point（接入点）

接入点是**一组带名称的 GSE 接入地址，供其他管控单元连接使用**。它在管控单元中配置，用来告诉下游单元：“通过这些地址连接到这里。”

接入点是地址配置，不是一台 Proxy，也不是一个额外部署的服务。

## 为什么需要接入点

同一个管控单元，面向不同网络时，可访问的地址可能不同。例如，下游单元 A 可以访问上游 Proxy 的内网地址，而下游单元 B 只能访问它经过 NAT 映射的地址。上游单元可以为这两种访问方式分别配置接入点，下游选择自己能够访问的那个。

这样，**节点归属与连接地址可以分开描述**：管控单元组织节点，接入点描述其他单元怎样接入，不必为了提供另一组地址再划分一个管控单元。

## 接入点包含什么

| 地址组    | 用途                                     |
| --------- | ---------------------------------------- |
| `cluster` | GSE 信令通道，承载节点与上游的信令通信。 |
| `file`    | GSE 文件通道，承载单元之间的文件传输。   |
| `data`    | GSE 数据通道，承载节点数据上报。         |

每组可以填写多个地址。当前页面接受 `IPv4:端口` 格式，端口以实际 GSE 或 Proxy 服务配置为准。

> 这里的 `file` 是 GSE 文件传输服务地址，**不是安装包的 HTTP 下载地址**，也不是节点管理的回调地址。文件传输服务作为下游接入点的时候，端口号通常为`28930`，请注意与其通常作为agent access服务的端口`28925`区分开来。

## 如何使用

1. 在上游管控单元的创建或编辑页面，展开高级配置，在“下游接入点”中填写接入点名称和三组地址。地址应指向实际提供服务的 GSE 或 Proxy，并能从下游网络访问。
2. 创建或编辑下游非直连单元时，在“上游接入点”中依次选择上游管控区域、管控单元和接入点。上游可以位于另一个管控区域。
3. 一般情况下，三类通道使用同一个接入点即可。只有它们需要连接不同入口时，才在高级配置中分别选择。

例如，单元 B 需要经单元 A 连接上游：在 A 中配置一个 B 可访问的接入点，再将它选为 B 的上游。B 中的 Proxy 使用该接入点连接上游；B 中的 Agent 则连接 B 内的 Proxy。

“上游”和“下游”是相对关系：对 A 来说，这个接入点供下游使用；对 B 来说，它是上游入口。一个非直连单元也可以同时选择自己的上游，并配置接入点供其他单元使用。

## 与 Agent 直连配置的区别

安装 Agent 时，用户选择的是管控单元，不是接入点。

| 场景                 | 使用的地址                           |
| -------------------- | ------------------------------------ |
| 直连单元中的 Agent   | 所属单元的“直连配置”，直接连接 GSE。 |
| 非直连单元中的 Agent | 所属单元内可用 Proxy 的服务地址。    |
| 非直连单元中的 Proxy | 所属单元选定的上游接入点地址。       |

因此，“直连配置”供本单元 Agent 使用，“下游接入点”供其他单元的 Proxy 使用。二者即使指向同一套 GSE，也不应直接复制全部地址，尤其要区分 Agent 文件接入端口与 Proxy 文件通道的上游端口。

## 使用前提

- 接入点只记录地址，不会自动建立路由、NAT 或防火墙规则；三类通道都需要有实际可用的服务地址。
- 接入点地址由用户维护，不会随 Proxy 主机变化自动更新。
- 保存配置不会立即更新已有节点。修改 A 的接入点后，需要重载引用它的下游单元的 Proxy；修改 B 的上游选择后，需要重载 B 的 Proxy。
- 重载会重启 Proxy，应安排合适的操作时间，并确认重载任务成功。
